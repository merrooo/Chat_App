Reusable Capacitor Android setup and deployment (PowerShell)
============================================================

This project uses app-setup.json as the configuration you edit for each app.
The script updates Capacitor, Android app labels/ID/version, and the HTML entry
file. Keep the existing Android namespace and MainActivity package unchanged.

1. Put the web app in the project
---------------------------------

From the project root, place the web folder and its HTML file together:

    MyWeb\
      Home.html
      css\
      images\

Keep related CSS, JavaScript, and image files in the same web folder so relative
paths continue to work.

2. Edit app-setup.json
---------------------

Example:

    {
      "appName": "My App",
      "appId": "com.example.myapp",
      "webDir": "MyWeb",
      "entryHtml": "Home.html",
      "versionCode": 1,
      "versionName": "1.0.0"
    }

Use a unique reverse-DNS appId. Keep the same appId and signing key for updates
to an already-published app. A new appId installs as a separate Android app.
Increase versionCode for each release update.

3. Configure and sync in PowerShell
-----------------------------------

Open PowerShell in the repository root (the folder containing package.json),
then run:

    .\scripts\Configure-App.ps1
    npm install --no-audit --no-fund
    npx cap sync android

The script copies MyWeb\Home.html to MyWeb\index.html and updates
capacitor.config.json, android\app\build.gradle, AndroidManifest.xml, and
strings.xml. It stops with an error if the folder, HTML file, or required
Android files are missing.

4. Optional local debug install
-------------------------------

Local Android builds require JDK 21, the Android SDK, and (for installDebug)
USB debugging enabled on a connected phone.

    Set-Location android
    .\gradlew.bat installDebug

The debug APK is written to:

    android\app\build\outputs\apk\debug\app-debug.apk

5. Build a signed APK with GitHub Actions
-----------------------------------------

The workflow builds on a v* tag or when manually started from the Actions tab.
Store the signing information as GitHub Actions repository secrets:

    ANDROID_KEYSTORE_BASE64
    ANDROID_KEYSTORE_PASSWORD
    ANDROID_KEY_ALIAS
    ANDROID_KEY_PASSWORD

Do not put keystore passwords in this file, in PowerShell command history, or
in the repository. Do not commit a .keystore or .jks file. Reuse the same
signing key for updates to an existing app.

After committing and pushing the configured app:

    git status --short
    git add .gitignore app-setup.json capacitor.config.json android .github scripts "deploy App in Git.txt"
    git commit -m "Configure Android app"
    git push origin main

Then open GitHub -> Actions -> Build & Release APK -> Run workflow, select
main, and start the build. Alternatively, push a new version tag, for example:

    git tag v1.0.1
    git push origin v1.0.1

Download the APK from that successful workflow run's APK artifact. The APK
filename uses appName from app-setup.json.

Important repository safety notes
----------------------------------

Never delete .git, reinitialize this existing repository, force-push, or
delete/recreate a release tag to redeploy. Use a new version tag or run the
workflow manually.

This repository currently has release.keystore and node_modules tracked by Git.
The root .gitignore prevents newly-added files from being staged, but it does
not untrack files already committed. Check git status and the staged diff
before every push. Treat any keystore already pushed to a remote repository as
exposed; use a separately managed signing key for future releases.
